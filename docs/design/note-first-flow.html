Why the note goes first

Mapping used to fire once, against whatever page was showing. On this form that is the verification section — which holds none of the questions a consultation note can answer. The note no longer waits for the right page.

Nothing maps without a click

The panel notices a new section and says what it found there. It does not call the model until you press the button — four sections would otherwise be four calls nobody asked for.

The check screen stays

The parse is a first draft. These values are what the note is scrubbed against before it leaves the browser, so a wrong name here is a name left in the text — it is checked before anything is sent, then sealed.

Filling is still per step

Values are written into the section on screen when you press Fill, and never on a page change. Advancing a step is you using the insurer's form, not asking BreezeFill for anything.
